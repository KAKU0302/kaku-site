# core36 — CORE36 / 12TYPE 判定エンジン（scoring_version 0.2.0-draft）

開発・パイロット用の新しい診断エンジンです。**既存の旧30問・16タイプの診断、決済、メール送信、共有、購入履歴とは完全に独立**しており、`index.html` からは読み込まれません。

## 位置づけ

- KAKUの自己理解の中心は **CORE6（6軸の回答傾向）**。12TYPEは「いちばん近い代表タイプ」を示す入口です。
- 6軸の結果（`axes`）は12TYPEの判定表に依存しません（テストで確認）。代表タイプが僅差で入れ替わっても、軸の読みは変わりません。
- 設問・プロフィール・しきい値はすべて**暫定**です。信頼性・妥当性の検証は済んでいません。心理学の概念は着想の参考にした段階で、両極の組み立てや場面の分け方はKAKU独自の仮説です。

## 判定ルール（0.2.0-draft）

- 回答：左右2つの文のうち近い方を5段階で選ぶ。A極の文の左右は問ごとに入れ替え（各軸3対3）。
- 軸の位置：`50 + 25 × 平均`（0〜100、50が中立）。平均が±0.5以上で「寄り」、未満は「どちらにも寄らない」。
- 場面による違い：両場面の平均が逆符号でそれぞれ|1.0|以上のときだけ「今回の回答では、場面によって違いが見られた」。**性質とは断定しない**。タイプ判定には使わない。
- 12TYPE：各タイプの「決める軸2つ（重み1）＋補助の軸1つ（重み0.5）」の目標位置（50±25）との重み付き距離が最小のタイプ。
- 僅差：1位と2位の距離の差が3未満なら、2番目に近いタイプを補足。
- 完全な同点：決める軸だけの距離 → 固定順。同点が4タイプ以上、または寄る軸が1つもない場合は**無理に分類しない**。
- 近さ弱め：寄る軸が1つだけ、または距離が25以上のときは、最も近いタイプを「近さは弱め」として表示。
- 無効回答：整数の1〜5以外は無効。1軸で有効回答が5問未満なら「未完了」（タイプを出さない）。

## パイロット

1. `test.html` を開き、参加コード（例 P01）を入れて回答。結果とアンケートを保存（この端末のブラウザ内にだけ保存）。
2. 2週間後に同じ参加コードで「再回答」。
3. 「JSONを書き出す」で全履歴をファイルにし、`tools/analyze-pilot.js` で分析。
4. 見る項目：軸ごとの一貫性（特にBONDのC05・C35と、LOGIC–BOND間の相関）、2週間後のCORE6の一致、設問の分かりやすさ、結果への納得感、判定理由の理解、軸の読みの実感。

「表示した1〜2タイプに再回答のタイプが入る割合60%以上」は**暫定の開発目標**であり、科学的に検証された基準ではありません。

## プレビュー（試作）

```bash
node core36/tools/build-preview.js        # preview/dist/preview.html（ローカル確認用）と artifact.html（非公開ページ用の断片）
node core36/tests/e2e-preview.js          # スマホ幅（375×812）で 同意→36問→結果→BOOK5章→感想→書き出し→再回答の比較 を通すブラウザ確認
```

- 流れ：同意 → 36問（設問ごとに「違和感」を記録可）→ CORE6＋12TYPE（判定理由つき）→ PERSONAL BOOK 5章 → 感想 → 再回答の比較。
- 既存の12TYPEのキャラクター画像（再圧縮なし）・色・名前は、既存の `types-data.js` と画像ファイルを**読み取って**埋め込む（既存ファイルは変更しない）。希少度は持ち込まない。
- 配布：認証つきの非公開ページ（claude.ai Artifact、作成者のみ閲覧可）として公開。公開版サイトとはオリジンも保存領域も別。
- **このフォルダを公開版のリポジトリにそのまま入れないでください。** `preview/dist/` が公開URLから見えてしまいます。外部の参加者向けに配るときは、Vercel の Deployment Protection などで認証を付けた別プロジェクトにしてください。

### PERSONAL BOOK の選択ルール（content_version book-0.1.0-draft）

- 材料は6軸の回答だけ（VALUE・STATE・継続記録は使わない。必要な内容は「まだ読めないこと」として明示）。
- 寄りのある軸 ＝ 読みが a / b の軸（|平均|≥0.5、場面による違いが出た軸は除く）。並びは |平均| の大きい順、同じなら固定順。
- 第1章：全体像（寄り0/1/2以上で文章が変わる）・6軸の地図・代表タイプ（判定理由）・場面による違い。
- 第2章：寄りの上位3軸の「武器」。第3章：上位2軸×（力が出やすい／噛み合いにくい）＝KAKU仮説。
- 第4章：影響力・共鳴力・解析力を、読みの種類（A寄り／B寄り／寄らない／場面による違い）ごとの文章で。
- 第5章：上位3軸から「力を出しやすい条件」「気づいておくと楽な場面」「試してみること（選べる3件）」。
- 第2〜5章は代表タイプに依存しない（僅差でタイプが入れ替わっても一字一句同じ。テストで確認）。

### 開発用の保存と書き出しの仕様

- 外部送信：**しない**。通信を行うコードを持たない（テストで、通信APIの不使用・外部URLの不在・実ブラウザでの通信0件を確認）。
- 保存：同意の画面で「保存する」を選んだときだけ、`localStorage` のキー `kaku_core36_preview_store_v1` に保存（同意の記録、参加コード、36問の回答と設問ごとの時間、違和感、結果の要約、BOOKの反応・メモ、感想、scoring_version）。選ばなければ画面を閉じると消える。氏名・メール・生年月日は取らない。
- 書き出し：利用者が「回答データを書き出す」を押したときだけ。JSON（`kaku-core36-export/1`）。`scoring_version`、`definition_hash`、BOOKの文章バージョン、再回答の比較結果を含み、`tools/analyze-pilot.js` にそのまま渡せる。保存できない環境では画面に表示してコピーできる。
- 削除：「データ」画面から、画面内の確認のあとに全削除。

## 注意

- このフォルダ全体がサイトの静的ファイルと同じ場所にあるため、デプロイ方法によっては公開URLから見えます。`test.html` には `noindex` を付けていますが、本番に載せない設定は別途必要です。
- 新版の結果は、旧版の決済スナップショット（`typeId` と `core6` が必須）の形式ではありません。プレビューのPERSONAL BOOKは、決済スナップショットとは別の仕組みです。旧購入履歴の復元には影響しません。
- 旧4タイプ（mediator / builder / adventurer / finisher）のデータは `types-data.js` に残してあり、新版は出力しません。
